# 🌿 Git 工具

ToolDock 擴充：簡單好上手的 Git 圖形介面。複製儲存庫、暫存與提交、推送與拉取，查看分支線圖，並一段一段解決合併衝突。

這是**選用的擴充，不隨平台內建**：從 ToolDock 的擴充商店安裝，或下載 `.tbx` 後在「擴充管理」安裝。需要 ToolDock 1.6.0 以上，以及電腦上已安裝 [Git](https://git-scm.com/downloads)。

## 功能

- **儲存庫**
  - 複製遠端儲存庫（clone），輸入網址後自動帶出資料夾名稱，下載時狀態列顯示進度，可以取消。
  - 加入本機的儲存庫；選到的資料夾不是儲存庫時，可以直接建立（init）。
  - 用下拉選單切換多個儲存庫；從清單移除不會刪除檔案。
- **變更與提交**
  - 異動分成合併衝突、已暫存、變更、未追蹤四組，每個檔案可以暫存、取消暫存、捨棄；雙擊檔案也能暫存或取消暫存。
  - 點檔案開啟並排或行內的差異比對，沒有變動的段落自動摺疊。
  - 輸入訊息後提交（⌘Enter／Ctrl+Enter）；沒有暫存任何檔案時，會詢問是否全部暫存後提交。可以修正上一次提交（amend）。
  - 還沒設定提交者名稱與 email 時，會請你填寫（可以套用到整台電腦或只套用到這個儲存庫）。
- **推送、拉取、擷取**
  - 工具列顯示領先／落後遠端的提交數。
  - 推送時目前分支還沒有遠端分支，會自動建立並設定追蹤；沒有設定遠端時會請你輸入網址。
  - 推送被拒絕（遠端有新的提交）時，可以選擇「先拉取再推送」或「強制推送」（`--force-with-lease`）。
  - 拉取方式可以在設定選擇合併、重定基底或只允許快轉。
  - 網路操作會顯示進度、可以取消，超過設定的時間自動中止。
- **分支線圖**
  - 以彩色線條畫出所有分支的提交歷史與合併；目前所在的提交以空心圈標示，分支、遠端分支與標籤直接標在提交上。
  - 可以只看目前分支、搜尋訊息／作者／提交編號，捲到底部載入更多。
  - 點提交查看完整訊息、作者、父提交與變更的檔案，再點檔案看差異。
  - 右鍵提交：建立分支或標籤、切換、合併、揀選（cherry-pick）、還原（revert）、重設目前分支（soft／mixed／hard）。
- **分支**
  - 本機分支、遠端分支、標籤與遠端清單；雙擊切換分支，切換遠端分支時會建立追蹤它的本機分支。
  - 建立、重新命名、刪除分支（還有沒合併的提交時會再確認），刪除遠端分支，新增或移除遠端。
  - 合併其他分支到目前分支。
  - 切換、合併、拉取時如果有未提交的變更會被覆蓋，可以選擇「儲藏後繼續」，完成後自動取回。
- **衝突解決**
  - 合併、拉取、揀選或取回儲藏發生衝突時，自動切到衝突檔案，上方提示合併進行中，可以隨時中止。
  - 每一處衝突並排顯示**目前**與**傳入**的內容（diff3 格式時也能展開共同祖先），選擇採用目前、採用傳入、兩者都保留（任一方在前），或直接編輯結果。
  - 全部處理後「儲存並標示已解決」：寫入檔案並暫存；保留原本的換行字元與 BOM。所有衝突都解決後按「完成合併」。
  - 一邊刪除、一邊修改的衝突與二進位檔案，以整個檔案選擇保留、採用哪一方或刪除。
- **SSH 金鑰**（「＋」選單、儲存庫選單或歡迎畫面的「🔑 SSH 金鑰」）
  - 列出 `~/.ssh` 中的金鑰：類型、註解、指紋（與 `ssh-keygen -l` 相同），並標示 ssh 會不會自動使用它、是否已過時、哪個儲存庫正在使用。
  - **產生金鑰**：Ed25519（建議）或 RSA 4096，可以設密碼；不會覆蓋已有的檔案。產生後公鑰自動複製到剪貼簿，可以直接開啟 GitHub、GitLab、Bitbucket 的「新增 SSH 金鑰」頁面貼上。
  - **取得公鑰**：每把金鑰都能一鍵複製公鑰（只讀取 `.pub`，私鑰內容不會被讀取或顯示）。
  - **切換金鑰**：為目前的儲存庫，或所有儲存庫（全域預設）指定要用哪一把金鑰。同一個網站有多個帳號（例如公司與個人的 GitHub）時特別有用。複製（clone）時也能先選金鑰。設定寫在 git 的 `core.sshCommand`（`ssh -i "<私鑰>" -o IdentitiesOnly=yes`），不會修改 `~/.ssh/config`；已經有自訂的 `core.sshCommand` 時，取代前會先確認。
  - **測試連線**：用指定的金鑰執行 `ssh -T`，顯示網站回應的帳號名稱；第一次連線時記住主機金鑰。
  - 遠端還是 HTTPS 網址時（GitHub、GitLab、Bitbucket），可以一鍵改成 SSH 網址。
  - 推送、拉取時被拒絕（`Permission denied (publickey)`）或主機金鑰未確認時，錯誤訊息可以直接開啟 SSH 金鑰面板。
- **和其他工具共享專案**（需要 ToolDock 1.4.0 以上的資料交換）
  - 儲存庫選單「在程式碼編輯器開啟」：把目前的儲存庫交給程式碼編輯器，它會建立或切換到同一個專案。變更清單的檔案右鍵也能直接在程式碼編輯器開啟該檔案。沒有安裝能接收的工具時不顯示這個選項；安裝了多個時由平台讓你選擇。
  - 程式碼編輯器的「在 Git 工具開啟」會把專案交給這裡：自動找到儲存庫的根目錄（專案是子資料夾也可以），已經在清單中就直接切換，還不是儲存庫時詢問是否建立。
  - 儲存庫選單「分享專案（存成交換檔）…」：存成 `.tdx` 檔傳給別人，對方在 ToolDock 開啟（或拖到視窗上）後，Git 工具會開啟帶好網址與分支的複製對話框，**確認後才下載**。對方清單中已經有同一個遠端的儲存庫時，會先詢問要開啟現有的還是另外複製一份。
- **儲藏（stash）**：儲藏目前的變更（可包含未追蹤的檔案），查看內容、套用、取出、刪除。
- **輸出**：工具列的「輸出」列出執行過的 git 指令、花費時間與 git 的原始訊息，方便查問題。

## 會讀寫的檔案與執行的程式

- **外部程式**：所有操作都是執行電腦上的 `git`，以參數陣列執行（不經過 shell），檔案路徑放在 `--` 之後，分支名稱不接受 `-` 開頭，不支援 `ext::` 網址。找不到 git 時依序嘗試常見的安裝位置，也可以在設定 `gitTool.gitPath` 指定。取消或逾時的網路操作會結束 git 與它啟動的子程序（Windows 上使用系統的 `taskkill`）。
- **會修改儲存庫**：暫存、提交、切換、合併、重設、儲藏、捨棄變更、刪除分支等都會改變你的儲存庫；捨棄、刪除、重設（hard）、強制推送前都會再確認。會修改儲存庫的操作一次只執行一個。
- **帳號密碼**：這個擴充不保存任何帳號、密碼或權杖。需要登入時交給系統的認證管理員（macOS 鑰匙圈、Windows Git Credential Manager）或 SSH 金鑰；git 不會跳出看不到的終端機提示（`GIT_TERMINAL_PROMPT=0`），沒有登入過的遠端會直接失敗並說明登入方式。
- **擴充資料**：儲存庫清單與最後使用的儲存庫存在擴充的資料夾（`ctx.storage`）；畫面的寬度、比對模式等存在畫面的 localStorage。
- **監看**：選取的儲存庫會監看 `.git` 資料夾（HEAD、index、refs），在其他地方執行 git 指令後自動重新整理。
- **網路**：只有 clone、fetch、pull、push、刪除遠端分支，以及 SSH 金鑰面板的「測試連線」會連線到外部主機。
- **SSH 金鑰**：
  - 產生金鑰時執行 `ssh-keygen`，寫入 `~/.ssh/<檔名>` 與 `<檔名>.pub`（`~/.ssh` 不存在時建立，權限 700）；不會覆蓋已有的檔案。密碼以 `-N` 參數交給 ssh-keygen，不會保存；ssh-keygen 執行的那一瞬間，同一台電腦上的其他程式可以從程序清單看到參數。
  - 列出金鑰時讀取 `~/.ssh/*.pub` 與 `~/.ssh/config`（只找 `IdentityFile`），不讀取私鑰。
  - 測試連線執行 `ssh -T -o BatchMode=yes -o StrictHostKeyChecking=accept-new`：第一次連到一台主機時把它的金鑰寫入 `~/.ssh/known_hosts`，已記住的主機金鑰改變時拒絕連線。
  - 切換金鑰時執行 `git config [--global] core.sshCommand`（全域設定寫在 `~/.gitconfig`）。
  - Windows 上優先使用 Git for Windows 附帶的 `ssh`、`ssh-keygen`，其次是系統內建的 OpenSSH。
- **通知與其他擴充**：不發通知，也不呼叫其他擴充的指令。和其他工具共享專案時透過平台的資料交換，交換包的格式是 `git-tool.project`（見下方〈專案交換格式〉）。
- **分享的交換檔**：只包含名稱、遠端網址與分支。網址中的帳號密碼（例如 `https://user:token@…`）會先去掉，不含本機路徑；只分享 https、ssh、git 與 `git@host:path` 形式的遠端，本機路徑的遠端不會放進去。

## 專案交換格式

`git-tool.project` v1，schema 在 [exchange/project.v1.schema.json](exchange/project.v1.schema.json)。其他擴充可以接收或產生這個格式，與 Git 工具互相開啟專案。

```jsonc
{
  "name": "tooldock-ext-git",
  "path": "/Users/me/code/tooldock-ext-git",   // 同一台電腦內交付時才有；可以是儲存庫中的子資料夾
  "remotes": [{ "name": "origin", "url": "https://github.com/tooldock-dev/tooldock-ext-git.git" }],
  "branch": "main",
  "file": "backend/index.js",                    // 選填，相對於 path，接收端可以直接開啟
  "line": 42
}
```

- `path` 與 `remotes` 至少要有一個。
- 從 `.tdx` 檔匯入（`info.origin` 為 `file`）時，接收端**必須忽略** `path`、`file`，只用 `remotes`：檔案可能來自別人，本機路徑沒有意義，也不能信任。
- 網址不得包含帳號密碼；接收端也要再檢查一次，只接受網路上的遠端，拒絕本機路徑、`file://`、`ext::`。
- 接收端不得自動下載，必須讓使用者看到實際的網址並確認。

## 限制

- 設了密碼的 SSH 金鑰需要先在終端機用 `ssh-add` 加入 ssh-agent（macOS：`ssh-add --apple-use-keychain ~/.ssh/<檔名>`），這裡不會詢問金鑰密碼。
- 切換金鑰只針對 git 的 SSH 連線；`~/.ssh/config` 中針對主機寫好的設定（例如 `Host` 別名）仍然有效，這裡不會修改它。
- 首次連線到需要登入的 HTTPS 遠端，請先在終端機對它執行一次 `git fetch` 或 `git push` 登入（GitHub 可用 `gh auth setup-git`），之後這裡就能使用。SSH 金鑰有密碼時需要先加入 ssh-agent。
- 不提供互動式重定基底（rebase -i）、子模組、Git LFS、逐行暫存（stage hunk）等進階功能。
- 差異比對不做語法高亮；檔案超過 10 MB 或為二進位檔時不顯示內容。
- 不是 UTF-8 的文字檔（例如 Big5）發生衝突時，只能整個檔案採用一方。
- 分享的交換檔只能讓對方複製第一個遠端（優先 origin），其他遠端需要對方自行新增。
- 在程式碼編輯器切換專案時，Git 工具不會自動跟著切換（平台沒有共用的「目前專案」），需要從選單互相開啟。
- git 的訊息固定以英文執行（`LANGUAGE=en_US`）以便辨識錯誤，畫面上顯示整理過的中文說明；原始訊息在「輸出」中。

## 設定

| 設定 | 預設 | 說明 |
|---|---|---|
| `gitTool.gitPath` | （空白） | git 執行檔，留空時自動尋找 |
| `gitTool.pullMode` | `merge` | 拉取方式：`merge` 合併、`rebase` 重定基底（自動儲藏未提交的變更）、`ff-only` 只允許快轉 |
| `gitTool.logLimit` | 300 | 線圖一次載入的提交數 |
| `gitTool.cloneDir` | （空白） | 複製時預設放置的資料夾，留空為家目錄 |
| `gitTool.networkTimeout` | 600 | 網路操作逾時（秒） |

## 指令

| 指令 | 說明 |
|---|---|
| `gitTool.open` | 開啟 Git 工具 |
| `gitTool.clone` | 複製儲存庫 |
| `gitTool.addRepo` | 加入本機儲存庫 |
| `gitTool.sshKeys` | 開啟 SSH 金鑰面板 |
| `gitTool.pull`／`gitTool.push`／`gitTool.fetch` | 對目前選取的儲存庫拉取、推送、擷取；也能放在生命週期的 hook 中 |

`gitTool.pull` 與 `gitTool.push` 是受保護指令（`guarded`）：**其他擴充**第一次呼叫時，平台會先詢問你，並顯示要對哪個儲存庫拉取或推送。你自己從命令面板或生命週期 hook 執行不受影響。

## 測試

```bash
npm test
```

測試 SSH 金鑰（產生、指紋與 `ssh-keygen -l` 一致、不覆蓋、檔名與密碼檢查、列出時的標示、`core.sshCommand` 的設定與解析、複製時指定金鑰、HTTPS 轉 SSH 網址、連線結果判讀）；專案交換格式（去掉帳密、只接受網路遠端、從檔案匯入時忽略路徑、檔案不能跳出專案）、匯入（加入並選取、子資料夾、不是儲存庫、只開啟複製畫面、找出相同遠端）、分享成 `.tdx` 與指定分支複製；以及線圖排版（分支、合併、空欄重用）、衝突標記的解析與組合（CRLF、diff3、不完整的標記）、差異比對；並在暫存資料夾建立真的儲存庫與本機的 bare 遠端，實際執行暫存、提交、修正提交、推送（建立追蹤）、複製、被拒絕、擷取、拉取、分支、合併衝突與逐段解決、整個檔案採用一方、中止合併、切換遠端分支、儲藏、提交者身分、取消與逾時。需要安裝 git；測試不讀取你的全域 git 設定。

## 開發

需要先安裝 ToolDock 和 Node.js 18 以上。

| 指令 | 說明 |
|---|---|
| `npm run dev` | 以開發模式啟動 ToolDock 並載入這個擴充。存檔後會自動重新載入後端和畫面 |
| `npm run debug` | 同上，並開啟後端偵錯埠 `127.0.0.1:9229` |
| `npm run validate` | 檢查 manifest、檔案和相依套件 |
| `npm run pack` | 打包成 `dist/git-tool-<版本>.tbx` |
| `npm run install-local` | 打包並安裝到本機的 ToolDock |

| 檔案 | 職責 |
|---|---|
| `backend/git.js` | 執行 git（進度、取消、逾時、找不到 git 時的備援位置）、錯誤說明、輸出解析 |
| `backend/ops.js` | 各項儲存庫操作 |
| `backend/ssh.js` | SSH 金鑰：列出、產生、公鑰、`core.sshCommand`、測試連線 |
| `backend/project.js` | 專案交換格式 `git-tool.project`：建立、驗證、網址去帳密、比較遠端 |
| `backend/index.js` | 儲存庫清單、操作排隊、網路操作的進度與取消、`.git` 監看、畫面的處理函式 |
| `ui/git-core.js` | 純函式：線圖排版、衝突解析與組合、Myers 差異比對、時間格式 |
| `ui/app.js` | 畫面 |

## 發佈

推送 `v<版本>` tag 後，`.github/workflows/release.yml` 會驗證、測試、打包、簽章並建立 GitHub Release（需要 secret `TOOLDOCK_SIGNING_KEY`）。上架商店的步驟見 ToolDock 的 docs/DEVELOPER_GUIDE.md。
